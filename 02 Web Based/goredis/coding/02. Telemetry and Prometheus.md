# 02. Telemetry and Prometheus

This guide explains how to monitor cache operations by registering Prometheus metrics, mitigating high cardinality, exposing metric endpoints, and configuring Grafana dashboards.

---

## 📈 The Metrics Interface

The `goredis` library is instrumentation-agnostic. It defines a standard `Metrics` interface (in [metrics.go](file:///home/aruncs/Projects/Mine/goredis/metrics.go)) which has hooks for hits, misses, writes (sets), invalidations, and fetch latencies:

```go
type Metrics interface {
	Hit(key string)
	Miss(key string)
	Set(key string)
	Invalidate(tags []string)
	FetchDuration(key string, d time.Duration)
}
```

By default, the client initializes with `noopMetrics` (which performs no-op operations to avoid nil-checks).

## 🛠️ Registering Prometheus Metrics

To integrate Prometheus, import the `prometheus` sub-package and pass the metrics adapter during client instantiation.

### Mitigating High Cardinality
> [!WARNING]
> Do not map individual, high-cardinality cache keys (like `user:991242`) directly to Prometheus labels, as this will lead to Prometheus memory exhaustion.
> Use the **`KeyMapper`** function to group keys into low-cardinality string buckets.

### Code Setup Example

```go
package main

import (
	"log"
	"net/http"
	"strings"
	"time"

	"github.com/aruncs31s/goredis"
	goredisprom "github.com/aruncs31s/goredis/prometheus"
	"github.com/go-redis/redis/v8"
	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func main() {
	redisClient := redis.NewClient(&redis.Options{Addr: "localhost:6379"})

	// Initialize the Prometheus metrics collector
	promMetrics, err := goredisprom.New(goredisprom.Options{
		Namespace: "myapp",
		Subsystem: "cache",
		Registry:  prometheus.DefaultRegisterer,
		
		// Map high-cardinality keys to low-cardinality metric label groups
		KeyMapper: func(key string) string {
			if strings.HasPrefix(key, "product:") {
				return "product"
			}
			if strings.HasPrefix(key, "user:") {
				return "user"
			}
			return "other"
		},
	})
	if err != nil {
		log.Fatalf("Failed to initialize Prometheus metrics: %v", err)
	}

	// Register with WithMetrics option
	cache := goredis.New(redisClient, goredis.WithMetrics(promMetrics))

	// Expose the metrics endpoint on an HTTP server
	http.Handle("/metrics", promhttp.Handler())
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

## 🐋 Local Docker Monitoring Setup

To test telemetry locally, use the provided Docker Compose environment which includes both Prometheus and Grafana.

### 1. Prometheus Configuration (`prometheus.yml`)
Make sure Prometheus scrapes both itself and the Go application.
```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    scrape_interval: 5s
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'goredis-app'
    scrape_interval: 5s
    static_configs:
      # host.docker.internal resolves to the host machine gateway
      - targets: ['host.docker.internal:8080']
```

### 2. Docker Compose Configuration (`docker-compose.yml`)
```yaml
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"
    extra_hosts:
      - "host.docker.internal:host-gateway"

  grafana:
    image: grafana/grafana:9.1.0
    container_name: grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin
      - GF_AUTH_ANONYMOUS_ENABLED=true
      - GF_AUTH_ANONYMOUS_ORG_ROLE=Admin
    volumes:
      - ./grafana/provisioning/datasources:/etc/grafana/provisioning/datasources
      - ./grafana/provisioning/dashboards:/etc/grafana/provisioning/dashboards
      - ./grafana/dashboards:/var/lib/grafana/dashboards
```
