# 01. Getting Started

This guide covers package installation, setting up a connection, client initialization, and executing basic cache operations.

---

## 📦 Installation

To import the `goredis` library and its dependencies into your project, run:

```bash
# Install core package
go get github.com/aruncs31s/goredis

# Install go-redis driver
go get github.com/go-redis/redis/v8
```

---

## 🔌 Connecting to Redis

Start by setting up the underlying Redis client from `go-redis/redis/v8` and instantiating the `goredis` wrapper.

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/aruncs31s/goredis"
	"github.com/go-redis/redis/v8"
)

func main() {
	// Initialize the underlying Redis client
	redisClient := redis.NewClient(&redis.Options{
		Addr:     "localhost:6379",
		Password: "", // Set password if applicable
		DB:       0,  // Use default database
	})

	// Wrap it with goredis.New
	cache := goredis.New(redisClient)
	
	ctx := context.Background()
	// Cache is ready to use!
}
```

## ⚡ Basic Cache Operations

### 1. Store and Retrieve Values
You can cache any Go struct or native type. The library handles encoding/decoding automatically.

```go
type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

// 1. Store a value
user := User{ID: 42, Name: "Alice"}
err := cache.CacheSet(ctx, "user:42", user, 10*time.Minute)
if err != nil {
	panic(err)
}

// 2. Retrieve a value
var retrievedUser User
found, err := cache.CacheGet(ctx, "user:42", &retrievedUser)
if err != nil {
	panic(err)
}

if found {
	fmt.Printf("Cached User: %s\n", retrievedUser.Name)
}
```

### 2. Cache-Aside Pattern with `CacheGetOrFetch`
The library provides a convenient wrapper `CacheGetOrFetch` to handle the cache-aside pattern (Fetch on miss, set cache, and return) automatically.

```go
user, err := goredis.CacheGetOrFetch(ctx, cache, "user:42", 5*time.Minute,
	func() (*User, error) {
		// This fallback function is called ONLY on a cache miss
		// Fetch the user from your database here
		return &User{ID: 42, Name: "Alice"}, nil
	},
	"users-tag", // Optional tags for bulk invalidation
)
```

## 🏷️ Tag-Based Invalidation

You can assign tags to cache entries during creation, allowing you to invalidate group-level items in a single operation.

```go
// Both entries are cached under the "users" tag
_ = cache.CacheSet(ctx, "user:1", User{ID: 1}, 10*time.Minute, "users")
_ = cache.CacheSet(ctx, "user:2", User{ID: 2}, 10*time.Minute, "users")

// Later: Invalidate everything with the "users" tag
err := cache.InvalidateByTags(ctx, "users")
if err != nil {
	log.Printf("Failed to invalidate tags: %v", err)
}
// Both user:1 and user:2 are now cleared from the cache
```

> [!IMPORTANT]
> When using tag-based invalidation, the client internally registers keys under a set mapped to the tag. Stale references are cleaned automatically, but in high-write environments, consider running `CleanTag` periodically.
